Was ist der Innovator?

Ideen einreichen, bewerten,
zum Review bringen.

Eine Plattform für Innovationsmanagement: Mitarbeitende reichen Ideen ein, die Community bewertet sie, Organisator:innen führen sie durch einen strukturierten Review-Workflow.

💡 Ideen

Erstellen, veröffentlichen, versionieren — inkl. voller Revisionshistorie (Hibernate Envers).

👍 Voting

Likes in aktiven Phasen (PUBLISHED, REVIEW, APPROVED, PROGRESS).

✅ Review-Workflow

Rollenbasierte Status-Übergänge, zentral abgesichert im PermissionValidator.

Repository-Struktur · #251

Ein Monorepo, zwei unabhängige Apps

Zusammengeführt aus innovator-frontend und innovator-backend. Bewusst kein vereinheitlichendes Build-Tool — jede App behält Build, Dependencies und Versionierung.

apps/frontend

Angular · npm · eigener CLAUDE.md

Serve: npm start → :4200

apps/backend

Spring Boot · Maven · eigener CLAUDE.md

Run: ./mvnw spring-boot:run → :8080
Komfort-Wrapper im Root: ./run <start|test|lint|build> <frontend|backend> — ohne cd in apps/.
Frontend

Angular 21 · Standalone

  • Standalone-Components — keine NgModules, Bootstrap über app.config.ts
  • Funktionale HTTP-Interceptors (withInterceptors), keine Klassen
  • Runtime-Config statt environment.ts — assets/config.json wird beim Bootstrap geladen (backendApiUrl, authType)
  • Typisierte Routes mit roleGuard & Resolvern (ideaResolver)
  • i18n via $localize, Default Englisch, DE manuell gepflegt
VitestCypress (E2E) ESLint · simple-import-sortPrettier Node 24.15.x
Backend

Spring Boot 4 · Java 25

Package-Root de.fincon.reply.arenainnovator — klare Schichtung:

controller→ services→ repositorys→ JPA entities
  • MapStruct-Mapper DTO ↔ Entity — flache DTOs, Relationen nur via IDs; Service lädt echte Entities
  • Hibernate Envers für Revisionshistorie der Ideen (AuditReader)
  • Zentrale Fehlerbehandlung im GlobalExceptionHandler (@RestControllerAdvice)
  • ArchiveJob täglich 00:00 UTC — überfällige Ideen mit Retry/Backoff archivieren
CheckstyleSwagger UI /swagger-uiH2 (local) · Postgres (dev/demo)
Domänen-Kern · Idea-Lifecycle

Status treibt die Autorisierung

DRAFT→ PUBLISHED→ REVIEW→ APPROVED / REJECTED
…APPROVED → PROGRESS→ ARCHIVED
  • Übergänge per Ownership oder Rolle ORGANISATOR — aber nicht die eigenen Ideen (requireOrganisatorNotOwner)
  • DRAFT nur für Owner sichtbar — inkl. historischer Revisionen
  • Rollen: EMPLOYEE · ORGANISATOR · ADMIN
security/PermissionValidator · security/UserSession
