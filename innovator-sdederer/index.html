03 / 07

Backend im Querschnitt · apps/backend

Klare Schichtung von der HTTP-Kante zur DB

01controller HTTP-Kante — spricht ausschließlich DTOs
02services Geschäftslogik & Regeln
03repositoryssic Spring Data JPA — Persistenzzugriff
04entities JPA-Objektgraph — verschachtelte Relationen

MapStruct mappt den verschachtelten Entity-Graph auf flache DTOs. Relationen überqueren die API nur als IDs, nie als geschachtelte Objekte — der Contract bleibt flach.

04 / 07

Architektur · Monorepo (#251)

Ein Repo, zwei unabhängige Apps

apps/frontend

  • Angular Single-Page-App
  • eigene Abhängigkeiten & Versionierung
  • CI: frontend-*.yml, Pfadfilter apps/frontend/**

apps/backend

  • Spring Boot API
  • eigene Abhängigkeiten & Versionierung
  • CI: backend-*.yml, Pfadfilter apps/backend/**

./run <action> <app> ist ein Dispatcher, kein Build-System — bewusst keine vereinheitlichende Toolchain darüber. Doku liegt zentral im Repo (README.md, CLAUDE.md, MIGRATION.md).

05 / 07

Authentifizierung (#255 · #256)

Pragmatisch heute, föderiert als Ziel

Heute interim

security.mode = default

Lässt alle Requests durch — echte Auth wird vorgelagert angenommen.

security.mode = no-auth

HTTP Basic; Passwort jedes Seed-Users ist "no-auth" — für lokale Dev & Demo.

Rollen: EMPLOYEE · ORGANISATOR · ADMIN

Ziel föderiert

  • 1GitHubIdentity Provider — vorhandenes Kontoextern
  • 2KeycloakRealm, GitHub als einzige Login-Methodekonfiguriert
  • 3OAuth2-Proxyvorgeschaltet, als Init-Container im Helm-Chartverdrahtet
  • 4ARENA AppOAuth2-Backend + Login-Flowin Arbeit

Bewusst sequenziert: Die Infrastruktur bleibt aus, bis die App-Seite steht — dann ist das Aktivieren ein Schalter, kein Projekt.

06 / 07

Deployment & Infrastruktur

Container rein, GitOps raus

Multi-Stage Image Maven → Temurin JRE · non-root
→
gitops-config Helm-Charts, 1 pro App
→
ArgoCD auto-sync · self-heal · prune
→
Cluster Podman / Docker

Das Build-Image ist mehrstufig: Maven kompiliert das JAR, die Build-Stage wird verworfen (Toolchain wird nie ausgeliefert), es läuft nur ein schlankes Temurin-JRE als non-root. Ein Merge in gitops-config ist das Deployment: ArgoCD gleicht den Cluster kontinuierlich mit Git ab — Drift wird geheilt, verwaiste Ressourcen werden entfernt.

Cluster-Zustand ≡ Repo-Zustand — kein Click-Ops.

Das große Ganze

Idee → Voting → Review → Projekt

Angular vorne, Spring Boot 4 / Java 25 hinten, PostgreSQL als Speicher — abgesichert über Keycloak & GitHub, mehrstufig containerisiert und per ArgoCD-GitOps über dev, demo und staging ausgerollt.
