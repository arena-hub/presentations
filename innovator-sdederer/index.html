Was der Innovator kann

Von der Idee zum Projekt

Mitarbeitende reichen Verbesserungsideen ein, das Team bewertet und prüft sie — angenommene Ideen werden zu echten Projekten.

FEAT · 01

Ideen einreichen

Strukturierte Erfassung von Ideen inkl. Beschreibung, Kategorie und Anhängen.

FEAT · 02

Voting

Das Team stimmt über eingereichte Ideen ab — die relevantesten steigen auf.

FEAT · 03

Review-Workflow

Ideen durchlaufen definierte Status bis zur Annahme und Projektüberführung.

04 / 07

Architektur · Monorepo (#251)

Ein Repo, klar getrennte Apps

apps/frontend

  • Angular Single-Page-App
  • Kommuniziert per REST mit dem Backend
  • Wird als Container ausgeliefert

apps/backend

  • Spring Boot / Java 25 Service
  • Business-Logik & Persistenz
  • Stellt die REST API bereit

Frontend und Backend liegen zusammen im Monorepo — gemeinsame Konventionen, ein Ort für Doku (README.md, CLAUDE.md, MIGRATION.md) und eine durchgängige CI/CD-Pipeline.

Deployment & Infrastruktur

Container in, GitOps out

Build CI-Pipeline
→
Container Podman / Docker
→
Registry Image + Tag
→
Deploy ArgoCD · GitOps

Anwendungen werden containerisiert (Podman/Docker) und über ArgoCD nach dem GitOps-Prinzip ausgerollt: Der gewünschte Zustand steht in Git, ArgoCD gleicht das Cluster kontinuierlich damit ab.

07 / 07

Umgebungen & CI/CD

Drei Stufen bis zum Team

dev

Kontinuierliche Integration neuer Änderungen — schnelles Feedback.

demo

Vorführbarer Stand für Stakeholder und Reviews.

staging

Produktionsnahe Absicherung vor dem finalen Rollout.

Jeder Merge durchläuft die CI/CD-Pipeline: Build & Tests, Container-Build, dann GitOps-Deployment in die passende Umgebung.

Das große Ganze

Idee → Voting → Review → Projekt

Angular vorne, Spring Boot / Java 25 hinten, PostgreSQL als Speicher — abgesichert über Keycloak & GitHub, containerisiert und per ArgoCD-GitOps über dev, demo und staging ausgerollt.
