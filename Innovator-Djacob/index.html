05 / 06
Security · Identity

Authentication — pragmatic today, federated next

Today · two simple modesinterim

security.mode = default

Permits all requests at the security layer — real authentication is assumed to happen upstream of the app. The honest base configuration.

security.mode = no-auth

HTTP Basic where every seeded user’s password is literally "no-auth". A convenience for local dev and the demo, so the app is usable before a real identity provider is wired in — not an auth scheme.

building toward

Target · federated login

  1. GitHub identitythe account everyone already has — no separate ARENA logins
    external
  2. Keycloak realmGitHub as the sole login method inside the realm
    configured
  3. OAuth2 Proxyfronts the application; wired into the Helm chart as an init container
    wired, not on yet
  4. ARENA appOAuth2-aware backend + real login flow — in flight
    in flight

Plumbing already in place

  • Keycloak + OAuth2 Proxy in the deployment config (Helm init container)
  • GitHub configured as the identity provider inside the Keycloak realm

Agreed, needs building

  • Backend Spring Security OAuth2 configuration
  • Frontend login/redirect flow — replaces today’s Basic-auth prompt
  • New-user provisioning on first login no code creates a user today creates the local user record + a default role. This has no equivalent today, for anyone — worth building deliberately, not bolting on.
  • Keep name — and likely role — in sync on every login, not just at signup GitHub display names change; nothing updates them today
  • Logout kept in sync between the app and Keycloak
Open question · unresolved ?

Where should roles live? Keep EMPLOYEE / ORGANISATOR / ADMIN as the backend’s own model with Keycloak supplying identity only — or move authorization into Keycloak-issued claims? Genuinely undecided; depends on how hard the current role model turns out to be to migrate.

Deliberately sequenced: the plumbing stays switched off while the app-side work lands — then turning it on is a switch-flip, not a project.
